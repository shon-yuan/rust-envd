# Wiki — rust-envd

Start with [wiki/index.md](wiki/index.md), then verify relevant source and tests. Existing documents remain the source for protocol, platform and distribution details.

rust-envd implements the pinned official envd surface in Rust. The implemented [native CUA contract](docs/native-cua.md) adds `GET /cua/tools`, `POST /cua/call`, `GET /cua/health` and `GET /cua/metrics` inside the existing S0 routing/authentication stack. All CUA paths require completed initialization and a nonempty current `X-Access-Token`; Bearer, Basic and file signatures cannot substitute. The only engine is envd's directly linked in-process desktop registry, without MCP, an extension framework, workers, helpers or mode selection. Production startup rejects old `COORWORKER_CUA_*` variables and `CUA_ENV_TOKEN`.

The default build enables `cua-desktop`; desktop dependencies stay optional via `--no-default-features` for the desktop-free base/static build. Windows SCM-attached processes, Session 0 (including service successors there) and unknown sessions report unavailable before constructing a registry; S0 filesystem/process services remain available. Model/provider credentials belong in AgentHost.
